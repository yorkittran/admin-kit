# ADR 003: Vite SPA over Next.js

## Context

The frontend is an authenticated internal dashboard behind a login wall. A separate API server (Elysia) already exists. Decided 2026-06-10.

## Options

- **Next.js** — RSC, SSR, the default React meta-framework; server features are dead weight when the BE is separate, and SSR/SEO is irrelevant behind auth.
- **Vite SPA + TanStack Router** — instant dev server, file-based routing with typed search params and route context, static deploy (nginx); no SSR if ever needed later.

## Decision

Vite SPA with TanStack Router (file-based). Internal tools need no SEO and no SSR; a static bundle behind nginx is the simplest deployable unit.

## Consequences

- Deploy = static files + SPA fallback; no Node server for the frontend.
- Route tree (`routeTree.gen.ts`) is generated by the router plugin — never hand-edited.
- The running dev server's router plugin scaffolds stub files over briefly-missing routes during git branch switches — stop the dev server before switching branches.
- Auth gating happens client-side in `beforeLoad` (plus real enforcement on the API).
